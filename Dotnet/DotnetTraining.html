C# Type System

Definition

By default you think of a variable as “holding data.” In C# that is only true for value types. A reference type variable holds an arrow to an object on the heap — so two variables can point at the same box.
  • Value types: int, bool, struct, enum — assignment copies the bits.
  • Reference types: class, arrays, delegate — assignment copies the reference (same object).
  • Boxing: wrapping a value in object moves it to the heap — allocation; avoid in hot loops.
  • struct vs class: small immutable value → struct; identity / inheritance / large mutable state → class.

Step-by-step (beginner friendly)

  • Step 1 — Value type vs reference type
    A value type variable holds the bits of the value itself. A reference type variable holds a pointer to an object on the heap.
    # INPUT
    int a = 10; int b = a; // copy the value b = 99; Console.WriteLine(a); // 10 var list1 = new List<int> { 1, 2 }; var list2 = list1; // copy REFERENCE list2.Add(3); Console.WriteLine(list1.Count); // 3
    # OUTPUT (same line as each WriteLine)
    10 3

    Takeaway: value = copy the number · reference = copy the arrow (both can point at one box).

  • Step 2 — Boxing and unboxing
    Boxing stores a value type inside an object on the heap. It allocates and copies — fine occasionally, expensive in a hot loop.
    # INPUT
    int n = 42; object boxed = n; // boxing — heap alloc int back = (int)boxed; // unboxing Console.WriteLine(back);
    # OUTPUT (same line as each WriteLine)
    42

    Level-3 answer: name a place boxing hurt performance (e.g. ArrayList of ints) and what you changed (prefer List<int>).

  • Step 3 — struct vs class
    Use struct for small, immutable, logical-value data; class when you need identity, inheritance, or large mutable state.
    # INPUT
    readonly struct Money { public decimal Amount { get; } public string Currency { get; } public Money(decimal amount, string currency) => (Amount, Currency) = (amount, currency); } var fee = new Money(9.99m, "USD"); var copy = fee; // value copy Console.WriteLine(copy.Amount); class Order { public int Id { get; set; } } var o1 = new Order { Id = 1 }; var o2 = o1; // same object o2.Id = 99; Console.WriteLine(o1.Id); // 99 — shared
    # OUTPUT (same line as each WriteLine)
    9.99 99

    Takeaway: when unsure, start with class; switch to struct only when value semantics are clear.

Definition

Memory kept climbing after traffic fell, so the team separated allocation rate from retained objects and leaked native resources.
  • Generations: The GC promotes surviving objects; long-lived references can move objects into older generations.
  • LOH: Large allocations generally land on the Large Object Heap and can increase pause and fragmentation pressure.
  • IDisposable: Dispose deterministic resources promptly with using; GC timing is not resource cleanup.
  • Diagnosis: Use counters and dumps to distinguish high churn, rooted retention, and undisposed handles.

Async / Await
By default a method is synchronous — it holds the thread until it finishes. Add the async keyword so…

Definition

By default a method is synchronous — it holds the thread until it finishes. Add the async keyword so the method can release the thread while waiting; when the result is ready, work resumes (often on a thread-pool thread).
  • Normal method: sync — thread stays busy until the method returns.
  • Make it async: put async on the method and use await where you wait (HTTP, DB, file).
  • Why: await frees the thread during the wait so other work can run; when the Task completes, the method continues after await.
  • Not a new OS thread per call — it is about not blocking while waiting.
