Step-by-step (beginner friendly)

  • Step 1 — What is Python?
    Python is a language you write in text files ending in .py. You run them with the python command — no separate compile step like C#.
  • Step 2 — Interpreted, not machine code
    CPython reads your file, builds bytecode (.pyc), then executes that bytecode step by step. That is why we call Python interpreted.
  • Step 3 — Indentation = blocks
    Instead of { } braces, Python uses indentation (usually 4 spaces) after if, for, def.
  • Step 4 — Dynamic typing
    You do not write int x. A variable can hold a number, then a string — Python checks types at runtime.

Python keywords — deeper look

Indentation = the block structure in Python. No { } braces — spaces after : define what belongs to if, for, def.
Use when: every control-flow block.
Trap: mixing tabs and spaces → IndentationError.
Dynamic typing = a variable name can point to different types over time.
Example: x = 5 then x = "hi" — legal.
Not like C#: no int x declaration required.
Duck typing = use it if it behaves correctly — no interface keyword.
Meaning: if it walks like a duck and quacks like a duck, call .quack().

Interpreted vs compiled — step by step

  • C# path: .cs → compiler → IL (DLL) → JIT → native machine code → CPU runs it
  • Python path: .py → CPython compiles to bytecode → interpreter VM executes bytecode → result
  • Python feels instant because you run python file.py without a separate build step — bytecode is cached automatically in __pycache__/
  • Trade-off: generally slower than C#/C++ for CPU-heavy work; faster to write and test
C# developer tip: python file.py ≈ immediate run (no dotnet build). Replace { } with indents. Replace null with None.
Interview — questions & answers

A: We run the .py file using the Python interpreter. Internally, CPython converts it into bytecode (.pyc) and executes the bytecode step by step. So Python is both compiled to bytecode and interpreted by the Python virtual machine.

Q: How is Python different from C#?

A: No mandatory type declarations, indentation instead of braces, and duck typing — if it behaves like a duck, use it like a duck.

Definition

On Windows, install Python from python.org, add it to PATH, verify with python --version, then run code in the REPL, as a script (python file.py), or from Cursor/VS Code with the Python extension. Definition

Primitive types store a single value — for example int, float, str, and bool. Collection types store multiple values — for example list, tuple, set, and dict. This slide builds step by step: first primitives, then collections, then how dictionaries use keys.

Step-by-step (beginner friendly)

  • Step 1 — What are Python data types?
    A data type tells Python what kind of value is stored. Primitives hold one value.
    age = 25 # int price = 99.5 # float name = "Ravi" # str is_student = True # bool
  • Step 2 — Collection data types
    Collections hold multiple values.
    TypeSymbolCan change?
    List[]Yes
    Tuple()No
    Set{a, b}Yes
    Frozensetfrozenset()No
    Dictionary{key: value}Values can change
  • Step 3 — List: mutability, indexing, slicing
    Lists can grow and change. Index starts at 0; slice with [start:stop].
    nums = [10, 20, 30, 40] nums[0] # 10 — first item nums[-1] # 40 — last item nums[1:3] # [20, 30] — slice nums.append(50) # list grows
  • Step 4 — Tuple: immutability, packing, unpacking
    Tuples are fixed. Packing puts values together; unpacking assigns them to variables.
    point = (12.97, 80.22) # packing lat, lng = point # unpacking # point[0] = 15 # TypeError — cannot change def divide(a, b): return True, a / b # packs (ok, result) ok, val = divide(10, 2) # unpack
  • Step 5 — Set: uniqueness
    A set keeps only unique items — duplicates are removed automatically.
    tags = {"python", "code", "python"} print(tags) # {'python', 'code'} "python" in tags # True — fast membership
  • Step 6 — Frozenset: immutable set
    Frozenset is like a set but cannot change after creation. It can be a dictionary key.
    perms = frozenset({"read", "write"}) # perms.add("admin") # AttributeError — cannot change cache = {} cache[frozenset({1, 2})] = "combo" # OK as dict key
  • Step 7 — What is a dictionary?
    A dictionary stores key : value pairs.
    student = {"name": "Ravi", "age": 15} student["name"] # Ravi
  • Step 8 — What is a dictionary key?
    A key finds a value quickly — like a phone book.
    phone_book = {"Ravi": "99999", "Priya": "88888"}

    Key → Value: Ravi → 99999

  • Step 9 — Dictionary keys must not change
    Keys must stay the same after storing. Allowed: 10, "Ravi", (1, 2), frozenset({1,2}). Not allowed: [1, 2], {"x": 1}, plain set.
  • Step 10 — List cannot be a dictionary key
    grid = {} grid[[1, 2]] = "X"

    Output: TypeError: unhashable type: 'list'

  • Step 11 — Dictionary cannot be a dictionary key
    cache = {} cache[{"id": 1}] = "data"

    Output: TypeError: unhashable type: 'dict'

  • Step 12 — Tuple and frozenset as keys
    grid = {} grid[(1, 2)] = "cell" grid[frozenset({"a", "b"})] = "perms"

    Both work — immutable, so hash stays fixed.

  • Step 13 — Summary
    Data typeMutable?Dict key?
    int, float, str, boolNoYes
    tupleNoYes
    frozensetNoYes
    listYesNo
    dictYesNo
    setYesNo

Interview — questions & answers

Q: What is the difference between set and frozenset?

A: set is mutable — add/remove items. frozenset is immutable like tuple. Use frozenset when you need a set as a dict key.

Q: What is the difference between list and tuple?

A: List can append, slice, and change items. Tuple is fixed — good for coordinates, return values, and dict keys.

Q: Why can't you use a list as a dict key?

A: grid[[1,2]] = "X" → TypeError: unhashable type: 'list'. The list could change after storing.

Q: What types can be dictionary keys?

A: Immutable types: int, str, tuple, frozenset, bool, float. Not list, dict, or mutable set.

Definition

Operators perform computation and comparison: arithmetic (+, -, *, /, //, %, **), comparison (==, !=, <), logical (and, or, not), identity (is), membership (in), and bitwise (&, |, ^, ~, <<, >>).

Step-by-step (beginner friendly)

  • Step 1 — Arithmetic (+ - * / % // **)
    Python arithmetic operators work on numbers and some sequences.
    a, b = 10, 4 a + b # 14 a - b # 6 a * b # 40 a / b # 2.5 (always float in Python 3) a % b # 2 (remainder) a // b # 2 (floor division) a ** b # 10000 (power)

    Key rule: / always returns float. Use // when you need whole-number division.

  • Step 2 — Comparison & Logical
    Comparison operators return True or False. Logical operators combine conditions.
    ComparisonMeaning
    ==equal value
    !=not equal
    < > <= >=ordering
    age = 20 age >= 18 and age < 65 # True not (age < 18) # True score > 90 or bonus == True # short-circuit OR
  • Step 3 — Identity (is / is not) & Membership (in / not in)
    is checks same object in memory — not just equal values. Use is for None.
    a = [1, 2] b = [1, 2] a == b # True (same values) a is b # False (different list objects) x = None if x is None: print("no value") 3 in [1, 2, 3] # True "py" in "python" # True "z" not in "abc" # True
  • Step 4 — Bitwise
    Bitwise operators work on integer bits — common in flags, permissions, and low-level math.
    a, b = 5, 3 # 5 = 101, 3 = 011 a & b # 1 (AND) a | b # 7 (OR) a ^ b # 6 (XOR) ~a # -6 (NOT) a << 1 # 10 (left shift) a >> 1 # 2 (right shift)

    Use case: combine permission flags with |, test with &.

  • Step 5 — Assignment operators (+=, -=, …)
    Shorthand updates a variable in place — same idea as C# +=.
    n = 10 n += 5 # 15 (n = n + 5) n -= 3 # 12 n *= 2 # 24 n //= 4 # 6 n **= 2 # 36 flags = 0 flags |= 4 # set bit flags &= ~2 # clear bit

    All forms: = += -= *= /= //= %= **= &= |= ^= <<= >>=

  • Step 6 — Walrus operator (:=)
    Python 3.8+ — assign a value and use it inside the same expression (named after eyes looking like walrus tusks).
    data = ["a", "bb", "ccc"] if (n := len(data)) > 2: print(f"Got {n} items") # classic pattern: read until empty while (line := input("Name: ")) != "": print(f"Hello, {line}")

    Use when: you need the assigned value twice — avoids calling len(data) or input() twice.

Interview — questions & answers

Q: What is the difference between == and is?

A: == compares values. is compares object identity (same memory address). Two equal lists can be == but not is. Use is for None.

Q: What is a common division trap in Python 3?

A: 10 / 4 returns 2.5 (float). Use // for floor division (2) when you need integers.

Q: What does // vs % do together?

A: For integers: a == (a // b) * b + (a % b). Example: 10 // 4 = 2, 10 % 4 = 2.

Q: What is None and how do you test for it?

A: None means no value. Always use if x is None: — not x == None. There is only one None object in Python.

Q: When would you use bitwise operators?

A: Feature flags, network masks, fast multiply/divide by powers of 2 with shifts, or when working with binary protocols.

Q: What does += do?

A: n += 5 is equivalent to n = n + 5 — updates in place. Works for numbers, strings (s += "x"), and lists (lst += [1]).

Q: When should you use the walrus operator :=?

A: When you assign a value and immediately need it in a condition or loop — e.g. if (n := len(items)) > 0:. Do not overuse; readability first.

Definition

Flow control directs execution: if/elif/else for branching, for/while for loops, break/continue for loop control, pass as a no-op placeholder, and an optional else on loops that runs when no break occurred.

Step-by-step (beginner friendly)

  • Step 1 — if / elif / else
    Run exactly one branch based on conditions. Indentation defines the block — no braces.
    score = 85 if score >= 90: grade = "A" elif score >= 75: grade = "B" else: grade = "C"

    Result: grade = "B"

  • Step 2 — for loop iteration & range()
    for item in sequence: visits each element. range() builds a sequence of integers.
    for fruit in ["apple", "mango"]: print(fruit) for i in range(5): # 0, 1, 2, 3, 4 print(i) for i in range(2, 10, 2): # 2, 4, 6, 8 print(i)
  • Step 3 — while loop, break & continue
    while repeats until the condition is false. break exits; continue skips to the next iteration.
    n = 0 while n < 5: n += 1 if n == 3: continue # skip printing 3 if n == 5: break # stop at 5 print(n)

    Output: 1, 2, 4

  • Step 4 — pass & else clause in loops
    pass = this block is intentionally empty for now. It is a stub — define the shape today, add real code later. When you implement it, remove pass and write your logic.
    pass does nothing at runtime, but Python accepts it as a valid statement when syntax requires an indented body.
    # stub — implement later def save_report(): pass # this block is empty for now # later, replace pass with real code: # def save_report(): # with open("report.txt", "w") as f: # f.write("data") class ValidationError(Exception): pass # empty exception class

    Loop else: runs only if the loop did not hit break.

    for x in [1, 2, 3]: if x == 99: break else: print("not found")

Interview — questions & answers

Q: How do blocks work without braces?

A: Indentation (usually 4 spaces) after a colon defines the block. Dedent ends the block. Mixing tabs and spaces causes IndentationError.

Q: When is for-else useful?

A: Search loops: loop to find an item; if found, break. The else clause runs only when nothing matched — clean 'not found' handling.

Q: range(5) vs range(2, 10, 2)?

A: range(5) → 0–4. range(start, stop, step) — stop is exclusive. range(2, 10, 2) → 2, 4, 6, 8.

Q: What is pass used for?

A: pass = this block is intentionally empty for now. Use it as a stub in an empty def, class, or unfinished branch. Later, remove pass and add your real code.

Q: What is the difference between if True and if False?

A: if True: block always runs once — usually a TODO stub with pass. if False: block never runs — used to temporarily disable code without deleting it.

Q: When should you NOT use if True: pass?

A: In finished production code — write the real logic directly, or use a proper def stub with a docstring. Remove if True once you implement the block.

Q: continue vs pass in a loop?

A: continue skips to the next iteration. pass does nothing but stays in the current iteration. Never use pass to skip loop items.

Definition

Comprehensions build collections in one expression: list [x for x in items], set {x for x in items}, dict {k: v for k, v in pairs}, and generator (x for x in items) which is lazy.

Step-by-step (beginner friendly)

  • Step 1 — List comprehension
    Build a new list in one expression — replaces loop + append.
    squares = [x * x for x in range(5)] # [0, 1, 4, 9, 16] evens = [x for x in range(10) if x % 2 == 0] # [0, 2, 4, 6, 8]

    Read it: "give me x*x for each x in range(5)"

  • Step 2 — Set comprehension
    Same syntax with curly braces — automatically removes duplicates.
    words = ["hi", "bye", "hi"] unique = {w.upper() for w in words} # {"HI", "BYE"}
  • Step 3 — Dictionary comprehension
    Build a dict from key-value expressions.
    nums = [1, 2, 3] sq_map = {n: n * n for n in nums} # {1: 1, 2: 4, 3: 9} filtered = {k: v for k, v in sq_map.items() if v > 1}
  • Step 4 — Generator expression
    Parentheses instead of brackets — lazy, yields one item at a time, saves memory.
    FeatureList compGenerator
    Syntax[...](...)
    MemoryAll at onceOne item at a time
    Reusable?YesExhausted after one pass
    gen = (x * x for x in range(1_000_000)) next(gen) # 0 next(gen) # 1

[...] list comprehension = build full list in memory now.
(...) generator expression = produce one item at a time, lazy.
Use generator when: large data — saves memory.
Comprehension filter — trailing if keeps matching items only.
Example: [x for x in nums if x % 2 == 0]

Interview — questions & answers

Q: Why use a comprehension over a for loop?

A: Shorter and often clearer for simple transforms. [n*n for n in range(10) if n%2==0] is easier to read than a 4-line loop with append.

Q: List comprehension vs generator expression?

A: List builds everything in memory. Generator yields one value at a time — better for large data or pipelines.

Q: Can comprehensions have nested loops?

A: Yes: [(x, y) for x in range(3) for y in range(2)] — same order as nested for loops.

Q: When should you NOT use a comprehension?

A: When logic is complex, has side effects, or needs multiple statements — use a regular for loop for readability.

Definition

Functions are defined with def. They support positional and keyword args, defaults, *args (extra positional), **kwargs (extra keyword), recursion, lambda for one-liners, LEGB scope lookup, and closures that capture outer variables.

Step-by-step (beginner friendly)

  • Step 1 — Positional & Keyword args
    Positional args are matched by order. Keyword args are matched by name. Defaults go in the signature.
    def greet(name, excited=False): msg = f"Hello, {name}!" return msg + "!!!" if excited else msg greet("Anu") # positional greet(name="Anu", excited=True) # keyword
  • Step 2 — *args & **kwargs
    Mutable default trap — never def f(items=[]). The same list is created once and shared across all calls. Use items=None and create a new list inside.
    *args collects extra positional args as a tuple. **kwargs collects extra keyword args as a dict.
    def log(msg, *args, **kwargs): print(msg, args, kwargs) log("start", 1, 2, level="debug") # start (1, 2) {'level': 'debug'}
  • Step 3 — Recursion
    A function calls itself until a base case stops it.
    def factorial(n): if n <= 1: return 1 return n * factorial(n - 1) factorial(5) # 120

    Warning: deep recursion can hit RecursionError — Python default limit ~1000.

  • Step 4 — Lambda
    Anonymous one-expression function — good for short callbacks.
    double = lambda x: x * 2 double(5) # 10 sorted(pairs, key=lambda p: p[1])
  • Step 5 — LEGB scope
    Python looks up names in order: Local → Enclosing → Global → Builtin.
    x = "global" def outer(): x = "enclosing" def inner(): x = "local" print(x) # local inner() outer()
  • Step 6 — Closures

Definition

threading runs concurrent tasks in one process but is limited by the GIL for CPU-bound work. multiprocessing and concurrent.futures bypass or manage this for parallel execution.

Step-by-step (beginner friendly)

  • Step 1 — threading.Thread & Lock
    Threads share memory within one process. Use Lock to prevent race conditions.
    import threading counter = 0 lock = threading.Lock() def increment(): global counter with lock: counter += 1 t = threading.Thread(target=increment) t.start() t.join()
  • Step 2 — GIL
    Global Interpreter Lock — only one thread executes Python bytecode at a time in CPython.
    Task typeThreads help?
    I/O-bound (network, disk)Yes
    CPU-bound (math, parsing)No — use multiprocessing

    Why I/O works: threads release the GIL while waiting on I/O.

  • Step 3 — multiprocessing workaround
    Separate processes bypass the GIL — each has its own Python interpreter and memory.
    from multiprocessing import Process def heavy(n): print(sum(i*i for i in range(n))) if __name__ == "__main__": p = Process(target=heavy, args=(1_000_000,)) p.start() p.join()

Q: What is the GIL?

A: Executor manages a pool, queues work, and returns futures. Cleaner than manually creating and joining many threads.

Definition

Quick reference mapping C# concepts to Python — syntax, stubs (pass vs { }), null/None, OOP, web, async, and tooling — for developers transitioning between languages.

Step-by-step (beginner friendly)

  • Step 1 — Syntax shifts
    No int x declarations, indentation not braces, self not this (but same idea). elif not else if. True/False are capitalized.
  • Step 2 — pass & empty blocks
    pass has no single C# keyword.
    Closest: empty { } when a method or block must exist but do nothing yet.
    Stronger stub: throw new NotImplementedException() ≈ raise NotImplementedError().
    C# interfaces declare methods without a body — Python uses pass inside class or def instead.
    # Python stub def save_report(): pass # C# equivalent # void SaveReport() { }
  • Step 3 — Type system & null
    Duck typing default; type hints optional. C# interfaces → Python ABC or duck typing.
    Null trap: C# x == null → Python x is None (not == None).
    Identity: C# ReferenceEquals → Python is.
  • Step 4 — Tooling & patterns
    venv + pip ≈ NuGet per project. pytest ≈ xUnit. Django/FastAPI ≈ ASP.NET.
    using ≈ with. LINQ .Where() ≈ list comprehension. Main() ≈ if __name__ == "__main__":.
  • Step 5 — Similarities
    Both OOP, both rich web stacks, try/except ≈ try/catch, both strong for APIs and automation. async/await exist in both — Python uses coroutines instead of Task<T>.

Interview — questions & answers

Q: What is the C# equivalent of pass?

A: No exact keyword. Empty { } for a stub block. throw new NotImplementedException() ≈ raise NotImplementedError() when the method must exist but is not ready. C# interfaces use declaration without body — Python uses pass in def or class.

Q: Coming from C#, what surprised you in Python?

A: Indentation as syntax, dynamic typing, mutable default argument trap, and that is vs == matters. Similarities: OOP, exceptions, and large package ecosystems.

Q: null vs None — how do you test?

A: C#: if (x == null). Python: if x is None: — use is, not ==, because there is only one None object.

Q: this vs self?

A: Same role — current instance. C# this is implicit in instance methods. Python requires self as the first parameter explicitly: def greet(self):.

Definition

PEPs document Python standards — PEP 8 style, PEP 257 docstrings, type hints, Zen of Python, and modern packaging via pyproject.toml.

Step-by-step (beginner friendly)

  • Step 1 — What is a PEP?
    PEP = Python Enhancement Proposal — design documents for language features, style, and packaging. Some are informational; others become official standards.
  • Step 2 — PEP 8 style
    4-space indent, snake_case for functions/variables, PascalCase for classes, imports grouped (stdlib → third-party → local). Linters enforce this in CI.
  • Step 3 — PEP 257 & type hints
    Docstrings describe modules, classes, and public functions. PEP 484/585 define type hints — use list[int] in Python 3.9+.
  • Step 4 — Packaging PEPs
    PEP 440 (versions), 508 (dependency specifiers), 518/621 (pyproject.toml) — how modern Python projects declare dependencies.

Python keywords — deeper look

PEP 8 = style convention, not syntax. snake_case functions, PascalCase classes, 4 spaces.
import this = Zen of Python (PEP 20).
pyproject.toml = modern project metadata + dependencies (PEP 621). Replaces setup.py for many projects.

Definition

Python uses reference counting plus a generational garbage collector for circular references. Understanding refs, gc, and weakref helps debug memory leaks.

Step-by-step (beginner friendly)

  • Step 1 — Reference counting
    Every object tracks how many references point to it. When count hits zero, memory is reclaimed immediately — fast for most objects.
  • Step 2 — Garbage collector
    Circular references (A→B→A) keep refcounts > 0 forever. The gc module periodically finds and breaks these cycles.
  • Step 3 — Generations
    GC uses three generations — young objects collected often, old objects rarely. Tuning is rare; know it exists for leak debugging.
  • Step 4 — Practical tips
    del removes a name, not necessarily the object. Use with for files. Long-lived caches can cause memory growth — profile before optimizing.

Python keywords — deeper look

sys.getrefcount = approximate reference count (debugging only).
gc.collect() = force garbage collection — use when hunting circular-reference leaks.
del name removes the binding — object lives if other references exist.
with = deterministic cleanup for files/sockets (not every object).

Interview — questions & answers

Q: How does Python free memory?

A: Primarily reference counting — when no names reference an object, it is freed. A generational GC handles circular references.

Q: What is a circular reference?

A: Two or more objects reference each other so refcounts never reach zero. Example: parent/child nodes pointing at each other — needs gc.collect() or weakref.

Q: del x vs x = None?

A: del x removes the name from the namespace. x = None rebinds to None but keeps the name. Neither guarantees instant destruction if other references exist.

    FastAPI supports async routes; use async SQLAlchemy (2.0 style) or run sync ORM in thread pool for I/O-bound DB work.
