Welcome! You know C# — Python will feel familiar yet simpler in syntax.

  • Use VS Code or Cursor with Python extension
  • Run scripts: python filename.py
  • REPL: type python in terminal

Hello World & Running Code
A Python program is a script executed line by line.

Definition

A Python program is a script executed line by line. print() sends output to the console. The if __name__ == '__main__' guard runs code only when the file is executed directly, not when imported.

How to explain in interview:

“print() is Python's Console.WriteLine. Every .py file runs top to bottom. I use if __name__ == '__main__' as the entry point — it only runs when I execute the file directly, similar to a Main method but optional and idiomatic for reusable modules.”

  • print() = C# Console.WriteLine()
  • Scripts run top-to-bottom
  • if __name__ == "__main__": guards entry point
print("Hello, Python!")
name = "Alex"
print(f"Hi, {name}!")

if __name__ == "__main__":
    print("Script entry point")
Coming from C#? C# needs static void Main(). Python runs the file directly; the __name__ guard is optional but professional.

Variables & Types
Variables are names bound to objects in memory.

Definition

Variables are names bound to objects in memory. Python is dynamically typed — you assign values without declaring types, but types exist at runtime and can be checked with type().

How to explain in interview:

“In Python I just write x = 10 — no int keyword. Python is dynamically typed, meaning the type is determined at runtime, but strongly typed, meaning it won't silently convert incompatible types like string plus integer. I can check types with type() when needed.”

  • Assign with x = 10 — no type keyword
  • type(x) checks runtime type
  • Variables are references to objects
age = 25
price = 9.99
name = "Riya"
is_active = True
print(type(age))   # <class 'int'>
Coming from C#? C#: int age = 25; Python: age = 25. Types are checked at runtime, not compile time.
Interview tip: Python is dynamically typed but strongly typed — "5" + 5 raises TypeError.

Booleans & None
bool represents True or False.

Definition

bool represents True or False. None is the singleton representing absence of a value (like null). Python uses truthiness — empty or zero values evaluate to False in conditionals.

How to explain in interview:

“None is Python's null — I always check with 'is None', not == None, because is checks identity. Truthiness is important: empty string, zero, empty list are all falsy. A common trap is bool('False') returns True because any non-empty string is truthy.”

  • None = C# null
  • Use is None, not == None
  • Truthiness: empty = False, non-empty = True
x = None
if x is None:
    print("No value")

print(bool(""))    # False
print(bool("hi"))  # True
print(bool(0))     # False
Interview trap: bool("False") is True — non-empty strings are truthy!

Loops: while, break, continue
A while loop repeats while a condition is true.

Definition

A while loop repeats while a condition is true. break exits the loop early; continue skips to the next iteration. Python uniquely allows an else clause on loops that runs if no break occurred.

How to explain in interview:

“while works the same conceptually as C#. break stops the loop, continue skips the rest of the current iteration. One Python-specific detail: a for/while else block runs only if the loop completed without hitting break — useful for search patterns.”

  • while condition: same idea as C#
  • break exits loop, continue skips iteration
  • Python loops can have else (runs if no break)
n = 5
while n > 0:
    print(n)
    n -= 1

for i in range(10):
    if i % 2 == 0:
        continue
    print(i)
Coming from C#? No i++ — use i += 1. No -- operator either.

Functions
Functions are reusable blocks defined with def.

Definition

Functions are reusable blocks defined with def. They support default parameters, *args for variable positional arguments, and **kwargs for variable keyword arguments. Functions are first-class objects.

How to explain in interview:

“I define functions with def name(params): and return sends a value back. *args collects extra positional args as a tuple, **kwargs collects keyword args as a dict. The classic trap is mutable default arguments — def f(lst=[]) shares the same list across calls; I use None instead.”

  • def name(params): — no access modifiers
  • Default args: def f(x, y=10)
  • *args tuple, **kwargs dict
def greet(name, msg="Hello"):
    return f"{msg}, {name}!"

def add_all(*args):
    return sum(args)

print(greet("Sam"))
print(add_all(1, 2, 3))
Interview trap: Never use mutable default args like def f(x, lst=[]) — shared across calls!

Lambda, map, filter
lambda creates small anonymous functions.

Definition

lambda creates small anonymous functions. map() transforms each element; filter() keeps elements matching a condition. These enable functional-style programming.

How to explain in interview:

“lambda is a one-line anonymous function — like x: x*2. map applies a function to every item, filter keeps items where the function returns True. In practice I often prefer list comprehensions, but I should know lambda for sorting: sorted(items, key=lambda x: x[1]).”

  • lambda x: x * 2 — anonymous one-liner
  • map(fn, iterable) — transform each
  • filter(fn, iterable) — keep matches
nums = [1, 2, 3, 4, 5]
doubled = list(map(lambda x: x*2, nums))
evens = list(filter(lambda x: x%2==0, nums))

pairs = [("amy",1), ("bob",3)]
pairs.sort(key=lambda p: p[1])
Coming from C#? Similar to LINQ .Select() and .Where(). List comprehensions are often preferred in Python.

OOP — Classes, Objects & Encapsulation
A class is a blueprint; an object is an instance.

Definition

A class is a blueprint; an object is an instance. Encapsulation bundles data and methods together and hides internals using the _underscore convention and @property.

How to explain in interview:

“I define a class with __init__ as constructor and self as the first parameter like C# this. For encapsulation I prefix internal fields with underscore — Python has no private keyword. @property gives controlled read access like a C# property getter.”

  • Class = blueprint; object = instance created from class
  • self = C# this (must be explicit first parameter)
  • Encapsulation: bundle data + methods; hide internals with _name convention
  • @property = controlled getter (like C# property get/set)
class BankAccount:
    def __init__(self, owner):
        self.owner = owner
        self._balance = 0          # "private" by convention

    def deposit(self, amount):
        self._balance += amount

    @property
    def balance(self):
        return self._balance

acct = BankAccount("Riya")
acct.deposit(100)
print(acct.balance)  # 100 — no direct _balance access
Coming from C#? No public/private keywords. Use _ prefix for internal use; __ (dunder) for name mangling (rare).

OOP — Inheritance & Polymorphism
Inheritance reuses parent class code via class Child(Parent).

Definition

Inheritance reuses parent class code via class Child(Parent). Polymorphism lets the same method call behave differently — through overriding or duck typing (if it has the method, it works).

How to explain in interview:

“I inherit with class Dog(Animal) and call super().__init__() like base constructor in C#. Polymorphism: I override speak() in Dog and Cat, loop a list of animals, each returns different sound. Duck typing means I don't need a formal interface — if it has the method, it works.”

  • Inheritance: class Dog(Animal): reuses parent code
  • super().__init__() calls parent constructor
  • Polymorphism: override speak() — same call, different output per type
  • Duck typing: “if it walks and quacks like a duck…” — no interface required
class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

for pet in [Dog(), Cat()]:      # polymorphism
    print(pet.speak())
Interview tip: Python supports multiple inheritance. Know MRO (Method Resolution Order). C# uses single inheritance + interfaces instead.

OOP — Abstraction & Magic Methods
Abstraction hides complex implementation behind a simple interface — using ABC + @abstractmethod (like C# abstract class) or duck typing.

Definition

Abstraction hides complex implementation behind a simple interface — using ABC + @abstractmethod (like C# abstract class) or duck typing. Magic methods (__str__, __eq__) customize object behavior.

How to explain in interview:

“For abstraction I use ABC from abc module with @abstractmethod — like C# abstract class. Duck typing is Python's informal alternative to interfaces. __str__ is for users like ToString(), __repr__ for debugging, __eq__ for Equals().”

  • Abstraction: hide implementation — use ABC + @abstractmethod (like C# abstract class)
  • Duck typing: any object with the right methods works — no formal interface
  • Magic methods: __str__, __repr__, __eq__ (like ToString, Equals)
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.14 * self.r ** 2

class Book:
    def __init__(self, title):
        self.title = title
    def __str__(self):
        return f"Book: {self.title}"
Coming from C#? C# interface IShape → Python ABC or duck typing. __str__ ≈ ToString(), __eq__ ≈ Equals().

File I/O
File I/O reads and writes data to the filesystem.

Definition

File I/O reads and writes data to the filesystem. The with statement (context manager) automatically closes files. Modes: 'r' read, 'w' write, 'a' append.

  • Always specify encoding="utf-8"
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("Hello\n")
    f.write("Python\n")

with open("notes.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.rstrip())
Coming from C#? Like using (var reader = ...). Python with is a context manager — same idea.

Definition

def two_sum(nums, target):
    seen = {}
    for i, v in enumerate(nums):
        need = target - v
        if need in seen:
            return [seen[need], i]
        seen[v] = i
    return []
Interview tip: Dict lookup is O(1) — use it for frequency and two-sum patterns.
